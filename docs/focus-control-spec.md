# 学霸模式与锁机开发规格

日期：2026-11-15。版本：完整截图覆盖稿 v2。状态：用户已要求把 12 张截图中的功能全部纳入文档；新增范围已记录，技术验证和新增交互仍须完成。当前只更新文档，未实现新增功能、执行设备改造或发布版本。

## 1. 目标与范围

在小猫专注现有待办、专注计时和五分钟休息之上，内置学霸模式、严格模式、通知拦截、全局与独立白名单、独立锁机以及完整的提升强制性选项。原先“第一轮仅全局名单、通知只免打扰、强制性只做诊断”的收缩范围，已被用户本次“我需要我们的文档包含这些功能”更新。

全部截图功能均属于本规格范围。分模块实施只表示开发顺序，不表示自动将困难功能删除或用权限说明页代替。尚未证明可行的效果必须有技术验证任务和结果，不能标为已实现。

2026-11-15 后续决定：用户要求优先复用 GitHub 现成模块，未找到的功能由本项目自行实现，完整范围不缩减，原有设计风格不变。源码复用与自研的执行规格见[完整实现规格](focus-control-implementation-spec.md)。该决定不把未经验证的系统能力标为已实现，也不自动确定第三方 GPL 代码的分发许可。

### 1.1 保留的基础

- 当前源码基线 0.2.3，Vue/TypeScript/Capacitor + Android Java/SQLite；Android min24、target36。
- 既有正计时、倒计时、暂停、记录、备份与五分钟休息继续保留；不重复引入第三方计时器或存储体系。
- 子待办长期保留，没有勾选完成或每日重置；倒计时提前结束仍保存实际投入。
- 严格模式只约束有明确终点的倒计时；正计时仍可手动正常结束，开始前明确提示。
- 首次所有保护开关关闭；按需解释权限，用户选择的下一轮配置与当前实际保护状态分别显示。
- 普通专注暂停时仍执行应用限制；进入休息释放本轮限制，再次专注按新一轮快照启用。
- 普通学霸模式临时放行 1/3/5 分钟，每轮最多三次，同一时刻一个应用；严格倒计时不提供临时放行。
- 原范围的进程恢复、重启中断、旧备份兼容、MuMu 内测与真机待补验规则继续有效；增强保护增加额外清理职责。

| 旧规则 | 本次目标 |

## 2. 页面与交互

### 2.1 学霸模式选项面板

待办页标题附近保留紧凑入口，显示未开启、待授权、已就绪、保护中或保护失效。点击打开与截图结构一致的纵向选项面板，采用本项目现有黑白灰、圆角、图标和 Sheet。

| 行项目 | 操作 | 内容 |
| --- | --- | --- |
| 学霸模式 | 开关 | 计时开始后限制白名单以外的应用 |
| 严格模式 | 开关 | 严格倒计时不能暂停、取消或提前完成 |
| 拦截通知 | 开关、帮助按钮 | 专注或锁机期间处理非白名单应用通知，结束后释放；与学霸/严格开关独立 |
| 提升强制性选项 | 子页面 | 图4的常规、防关闭、防卸载六项设置 |
| 学霸模式全局白名单 | 子页面 | 图标、名称、多选、搜索、系统应用显示切换、确认保存 |
| 权限与保护状态 | 子页面 | 各项授权、服务状态、支持情况、失败原因与恢复入口 |

开关表示用户意愿，不冒充已经授予权限或正在保护。只打开开关不会立即开始限制，必须启动专注或锁机。运行中编辑保存为下一轮配置，本轮使用启动时快照。

### 2.2 开启与权限说明

启用需要新权限的能力前，先解释用途、影响、本地处理方式及关闭方法，提供“暂不开启”“前往设置”。支持图2形式的短暂确认倒计时；具体时长作为界面参数，不硬编码为截图中的某一个倒计时瞬间。

从系统设置返回后重新检查授权；用户取消、拒绝、授权不完整都不能把保护显示为有效。按能力分别查询：无障碍、应用使用访问、悬浮显示、通知访问、勿扰访问、壁纸、后台运行及可选的设备策略身份，不一次索取所有权限。

### 2.3 全局白名单与独立白名单

- 全局白名单是默认配置，未启用独立名单的子待办与锁机配置在每次开始时继承最新全局名单。
- 每个子待办和可复用锁机配置都可以开启“使用独立白名单”，其用户名单替代全局用户名单，不与全局名单自动合并。
- 独立名单一旦保存，不随全局修改；选择“恢复跟随全局”后再继承，当前运行中的快照仍不改变。
- 必须区分“跟随全局”和“独立空名单”。独立空名单不是继承全局，仅保留本应用与必要系统功能例外。
- 列表支持图标、名称、搜索、多选、已选数量、确认保存，以及“显示系统 App/隐藏系统 App”切换。筛选不清空已选项。
- 小猫专注显示为固定允许且不可误取消；其他必要系统功能用独立说明标示，不混淆为用户随意编辑的名单。
- 学霸模式未开启时仍允许编辑名单，显示“当前尚未开启学霸模式，名单会在启用后生效”。
- 取消编辑不保存，确认才保存。未安装应用保留原包名配置并标记不可用，不自动误匹配同名应用。
- 自由专注默认使用全局名单；是否再添加一次性名单不属于这组截图必需范围。

### 2.4 帮助页面

必须提供可实际阅读的帮助内容，而不只是问号图标：

1. 学霸模式与严格模式的区别、单独/组合开启效果。
2. 全局名单与独立名单的继承、覆盖和恢复跟随。
3. 通知访问权限为何需要、仅本机处理什么、如何撤销。
4. 通知拦截与声音控制的区别，以及结束后释放的实际支持情况。
5. 第三方应用自己的锁屏页面、系统声音与系统版本限制。
6. 提升强制性的目的、六项选项分别生效的条件与代价。
7. 多任务隐藏不等于系统强停永远失效。
8. 服务失联、权限撤回、系统升级、电池限制及重新授权的排查步骤。
9. 图标隐藏、壁纸变化和异常结束后的恢复方法。
10. 普通用户模式与设备管理等额外身份的区别；只展示设备真实可用能力。

帮助文案随实测结果编写，不照抄竞品的“无法强制停止”“必然防卸载”等未证实结论。所有功能说明离线可读。

## 3. 专注、严格与临时放行

### 3.1 学霸模式执行

启动时固定本轮能力、有效名单及增强选项；识别受限应用后展示原生阻挡页，显示当前事项、剩余时间和返回专注入口。重复窗口事件不堆叠页面。

电话、紧急拨号、当前输入法、必要权限交互等必须有例外。桌面平时作为必要导航保留；用户另开“禁止桌面和多任务”时，按该增强规则处理，仍保留紧急和故障恢复路径。

### 3.2 严格模式

- 开启且本轮为倒计时时，原生入口拒绝暂停、取消和提前结束，不能只隐藏 Vue 按钮。
- 正计时不启用严格约束，开始前说明；不悄悄将正计时改成倒计时。
- 到期按原生实际时间结算，不依赖前端刷新；倒计时正常完成后沿用五分钟休息。
- 严格计时和“增强防退出”是两个维度；不能把严格模式当作自动取得系统强锁权限。

### 3.3 临时放行

普通学霸模式允许 1/3/5 分钟放行单个受限应用，整轮最多三次。更换目标前确认并结束上一放行，成功写入才扣次，取消/失败不扣，重复请求不重复扣。

放行期间继续计时；暂停不冻结期限，进程重建不延长期限或重置次数。结束、休息、重启中断和恢复备份清除放行。严格倒计时不提供入口，原生同样拒绝。

临时放行不永久修改白名单，也不同时放行目标应用通知；通知继续按本轮有效白名单处理。该操作规则按第12节的 to-spec 续写采用已有原型方案。

## 4. 通知拦截与结束释放

### 4.1 产品要求

- 正式增加截图中的“拦截通知”开关，功能是通知显示控制，不再用静音免打扰作为替代实现。
- 专注或锁机开始后，根据本轮有效白名单处理普通应用通知；白名单应用通知保留，非白名单应用的新通知进入本轮受控处理。
- 主目标是临时拦截、结束后释放，不能直接永久丢弃，再对用户宣称消息会恢复。
- 到期、普通提前结束、休息开始、取消锁机及故障恢复需要触发通知处理状态释放；不重复播报、不制造过期副本。
- 来电、紧急提醒、闹钟、本应用控制通知等必要消息分开处理。不能通过取消通知停止真实来电或第三方闹钟。
- 权限说明提供暂不开启、前往设置与本机离线处理说明；授权与实际监听连接状态分别显示。

### 4.2 技术路线与必须验证的事项

优先研究 NotificationListenerService 与系统通知暂缓机制；保留原通知身份和系统管理的优先级，而不是复制通知正文后以小猫身份伪造原应用消息。

已核查的关键门槛：公开的通知暂缓/查询机制从 API26 提供，API24—25 不具备同一条公开路线；普通通知监听器没有通用的提前立即释放接口，直接取消通知也不等于可逆暂存。因此“提前结束后立即恢复全部原通知”仍是明确待解决的需求，不能把一次 API 调用接通当作整项已完成。详见[安卓边界核查](references/focus-protection-android-boundaries.md)。

必须实测以下技术探针：
- 当前系统版本是否提供可用暂缓/查询机制，以及普通用户授权身份可做哪些操作。
- 正常倒计时结束、提前结束、正计时无预设结束、锁机取消、休息及重启时，原通知能否按目标时刻释放。
- 同一通知更新、原应用主动撤回、用户已读、分组通知、重复键、不可清除通知及工作资料边界。
- 进程退出、监听断开、权限撤回后，通知不被无限期隐藏。
- 旧 Android 的降级能力是否可实现目标；不因 min24 有通知监听器就宣称所有版本都支持完整暂存/释放。

若方案只做到永久清除、只能到预定期限释放、不能提前释放或无法恢复原通知，该差异必须成为明确的未完成项/支持限制，不能以“通知已释放”通过验收。需求仍保留在范围内，不静默删掉。

### 4.3 声音与隐私

通知暂存不保证通知从未响铃、第三方音频从未播放。原有“通知免打扰”保留为可选声音辅助：仅启停本应用自己的勿扰效果，不覆盖用户/其他应用规则，默认允许来电、闹钟和媒体；与通知隐藏效果分别说明。

仅在用户启用后处理必要通知数据；优先只保存本轮所需键、来源和处理状态，不建立长期通知正文数据库，不上传服务器，不将内容放入业务备份或调试日志。若最终技术路线必须增加本地敏感内容存储，应先补数据生命周期和用户说明。

## 5. 完整提升强制性选项

本页按截图分为“常规选项”“超强力：专注期间防关闭”“超强力：专注期间防卸载”。以下六项全部纳入开发范围，默认关闭，由用户单独授权启用。不能将本页整体替换成后台诊断。

| ID | 名称 | 目标行为 | 执行与恢复要求 |
| --- | --- | --- | --- |
| FORCE-01 | 待办计时中禁止桌面和多任务 | 本轮运行期间限制离开到桌面和最近任务页面，降低进入卸载/强退路径的机会 | 无障碍/系统策略按设备能力验证；与必要系统交互区分，到期或解除后恢复导航 |
| FORCE-02 | 在多任务列表中隐藏 | 活动保护期间隐藏本应用最近任务卡片，减少直接划掉入口 | 只修改本应用任务标志；结束恢复原状态，不将隐藏卡片宣称为系统强停免疫 |
| FORCE-03 | 锁机中禁止打开小猫主界面 | 独立锁机期间从普通启动入口只进入锁机控制界面，不进入待办/我的等业务主界面 | 统一路由和原生入口拦截；必要授权、帮助、紧急与故障恢复仍可达 |
| FORCE-04 | 桌面壁纸加固 | 提供用户主动启用的壁纸辅助保护，增强关联服务启动/重连能力 | 验证动态壁纸/关联服务路线；用户通过系统确认，记录原壁纸状态；能否完整恢复必须实测，不能静默更换或假称保活保证 |
| FORCE-05 | 自动防关闭 | 保护期间识别与本应用结束运行、卸载、关闭关键保护有关的系统入口，并按用户选择提高绕开成本 | 精确限定目标场景，不一概屏蔽所有设置；验证不同机型、语言和系统版本，提供故障解除与到期撤销 |
| FORCE-06 | 隐藏桌面图标 | 可选隐藏普通桌面启动图标，减少从图标进入卸载的入口 | 使用可恢复的启动入口策略；隐藏前验证通知/其他恢复入口可用，结束/故障恢复尝试恢复图标，用户随时有明确恢复说明 |

### 5.1 强制性边界

这些是主动选择的自控功能，不应写成普通安装后永久无法退出或卸载。普通模式、受管设备模式和额外授权后端分别报告能力，不使用“设备管理员”笼统代替 Device Owner 等具体身份。

需要设备策略才能做到的系统限制应列真实部署前提；若选择普通无障碍路线，应明确它只是窗口/操作层的限制。是否引入额外 SDK 属技术验证结果，不为用户自动激活高权限、重置设备或更改其他应用状态。

“在多任务隐藏”和“隐藏桌面图标”只减少相应入口；“桌面壁纸加固”也必须以实测说明增益，不能把这些文案组合成百分之百防强停的承诺。

### 5.2 启用与恢复

- 每项有帮助、所需权限、当前支持情况以及本轮实际启用状态；不能给失败操作显示成功勾选。
- 启用前说明影响，建立本轮原状态记录；拒绝某项权限不连带开启其他增强。
- 正常到期、普通结束、休息开始、重启中断、恢复备份时执行对应撤销/恢复，失败可见且可重试。
- 保留明示的故障恢复通道；恢复额外保护不伪造专注完成。隐藏图标和禁止主界面同时开启时，恢复通道需先验证。
- 只撤销本应用本轮施加的状态，不覆盖其他应用策略或用户在系统中主动做的新选择。
- 壁纸、图标和最近任务原状态记录与恢复必须有专项用例，不只检查开关持久化。

## 6. 独立锁机

锁机是独立于待办计时的限时应用控制场景，不是关闭屏幕，也不代表已获得设备所有者权限。

必须有锁机入口、时长选择、开始前权限检查、全局/独立白名单、增强选项、锁机进行中界面、剩余时间、到期释放和异常恢复。保持现有五栏导航，可通过待办/设置入口进入，不按竞品截图增加整套底部导航。

锁机可保存可复用配置；未设置独立名单时跟随全局，独立名单覆盖全局。通知与强制性规则使用同一锁机会话快照，“禁止打开主界面”只对活动锁机生效。

锁机使用明确结束时刻的倒计时，与专注共用单一活动控制所有权；已有专注或休息时提示先处理原会话，不并行叠加两套控制。按第12节补齐的原型操作规则：普通锁机可确认提前解除，严格锁机到点结束，锁机记录独立、不计专注统计、不自动休息，不能由实现者默认为专注记录。

图片未展示的周期锁机、定时排程、跨设备锁机和家长远程管理不因本节自动扩展。

## 7. 运行状态与异常

| 状态 | 应用限制 | 通知处理 | 增强保护 |
| --- | --- | --- | --- |
| 只有偏好开关打开 | 不执行 | 不执行 | 不执行 |
| 普通专注运行/暂停 | 按本轮有效名单执行 | 按有效名单处理，声音辅助独立 | 仅执行本轮成功启用项 |
| 严格倒计时运行 | 按本轮名单执行；原生禁止暂停/提前结束 | 同上 | 同上 |
| 正计时 | 正常限制，可手动结束；严格开关不生效 | 须验证无固定截止的通知释放策略 | 同上 |
| 独立锁机 | 按锁机快照执行 | 按锁机快照执行 | 包括可选禁止主界面 |
| 休息/本轮结束 | 释放 | 停止新拦截并释放本轮暂存；释放失败不报成功 | 恢复本轮更改 |
| 权限丢失/服务失联 | 实际失效项分别报告，保留计时 | 不谎报拦截中，处理暂存通知恢复 | 显示未完成清理与恢复入口 |
| 设备重启/备份恢复 | 按原规则中断/清理，不自动继续强锁 | 重建处理状态并验证释放 | 恢复图标、任务和其他自有更改，失败明确提示 |

进程重建不等于设备重启，应恢复会话、已用放行次数及本轮控制状态。用户开始时明确降级关闭的能力，不因后来授权自动添加；因运行中暂时失效而恢复授权的能力，只按本轮快照重新恢复。

## 8. 数据、备份与兼容

- 持久业务配置：三个功能偏好、全局名单、子待办独立名单、可复用锁机配置及其名单/增强偏好。
- 名单需要显式区分继承和独立；不使用空数组同时代表两种含义。新增字段缺省兼容旧数据。
- 活动状态：会话类型/标识、开始时能力快照、有效名单、期限、放行次数/目标、通知处理键及增强恢复日志。
- 业务备份包含可复用配置，不包含活动锁机/专注、临时通行、通知正文或系统授权；恢复后重新检测安装包和授权。
- 备份恢复沿用先结束活动专注要求，新锁机也需先结束；清理自己的保护后才替换业务数据，不能恢复后遗留隐藏图标或通知状态。
- 区分业务备份与本机升级恢复副本；两条恢复路径都要排除不应重新激活的运行态，并补校验。
- 当前 schemaVersion=1 的旧备份继续可读；是否新增字段或升级数据版本由兼容实现方案决定，不虚称现有空 onUpgrade 已完成迁移。

## 9. 技术接入与第三方复用

- 保留现有 Java/SQLite 会话依据；新增专注/锁机共用控制协调层，统一开始、恢复、结束和清理，防止两套计时/名单争用。
- 当前源码选择优先核对 Curbox 的应用控制/通知暂缓与 DetoxDroid 的防篡改/恢复模块，按文件确认许可与适配；Foqos 的 MIT 规则类保留为规则复用候选。未找到、无法适配或不满足许可条件的部分自行实现，不把第三方整个 SessionManager、Room、Hilt 或 Compose 应用搬入项目。来源选择以最新执行规格为准，不将任何候选整体引入视为完整功能已经满足。
- XXPermissions 用于设置引导与权限检测；库本身不授予权限或提供锁机、通知暂存、防卸载能力。
- 新增无障碍执行服务、原生阻挡页、锁机界面路由保护、通知监听/暂存模块及增强恢复管理器。
- 新增通知读取是本次范围变化，须更新 Manifest、权限说明、隐私说明、数据生命周期与故障报告脱敏。
- 图标隐藏、最近任务标志和壁纸服务分别模块化；不把所有保护塞入一个无法局部恢复的开关。
- 守住主线程、重复窗口去重、原生串行状态写入和幂等清理；事件处理读取不可变规则快照，不逐次触发带结算副作用的计时 read。
- EasyFloat 仍是后续悬浮计时候选；与这12图的核心功能分开排期，先验证 target36 兼容。
- 如某能力需要额外身份或系统版本，接口返回可用/需授权/受限/未支持及原因，不把功能默认静默替换成另一个效果。
- 所有复用保留版权、许可及必要声明；对完整 GPL 应用的代码复用另行核对，不因功能相似直接复制。

## 12. 决策与技术验证项

### 已由本次用户要求更新的范围

完整12图覆盖；图4六项增强；通知拦截与结束释放；全局+独立名单；独立锁机；系统App筛选；完整帮助与权限交互。保留此前未冲突的计时、休息、临时放行和异常恢复规则。

### 本次 to-spec 补齐的操作规则

1. 沿用已有原型方案：独立锁机使用可配置倒计时、单一活动控制所有权；普通锁机确认后可提前解除，取消确认则继续；严格锁机到点结束，原生拒绝暂停、取消和提前解除。锁机记录独立，不增加专注统计，也不自动进入五分钟休息。
2. 临时放行只改变应用可打开状态，不修改永久名单、不顺带释放通知；通知仍按本轮有效白名单处理。
3. 故障恢复从权限状态、帮助、锁机控制页和活动控制通知进入；隐藏图标/限制主界面前验证替代入口。原有 Sheet 列明影响，取消不操作；确认后按本轮记账尝试撤销应用限制、通知处理和增强更改，逐项报告恢复/失败/受限并可重试。计时和严格约束保留，不删偏好、不伪造正常完成；本轮主动撤销能力不因重连自动重新开启。
4. 通知暂存释放的版本/身份约束、壁纸原状态可恢复程度、防关闭支持范围是工程事实问题，先由开发验证，不让用户猜底层API。
5. 不改变现有五栏导航，不因截图含待办集/周总结等入口而扩展无关模块。

上述操作规则是在用户要求继续完成 to-spec 后，采用已有原型方案形成的执行默认，不声称用户此前逐项确认。平台边界、真实通知释放、壁纸恢复和机型效果仍由技术验证证明；完整验收场景见[执行规格](focus-control-implementation-spec.md)，不把规格补齐等同安卓功能已经完成。
