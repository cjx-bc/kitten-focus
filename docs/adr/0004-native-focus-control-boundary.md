# 学霸模式与锁机内置原生控制层，统一活动会话

学霸模式与新增独立锁机需要与现有计时、暂停、五分钟休息及备份恢复一致。根据用户已确认的同 APK 整合方向，以及后续“复用现成模块、缺失功能自行实现”的要求，优先评估已核验的 Curbox 应用控制/通知暂缓和 DetoxDroid 防篡改/恢复模块，Foqos 的 MIT 纯规则层保留为备选；保留现有 Java 引擎与 SQLite，在原生控制协调层统一活动会话快照及控制所有权，Vue 配置和显示状态。相较要求用户另装外部控制应用或整体引入另一套会话/数据库，这条路线避免计时与存储冲突；候选不符合本项目行为、技术边界或许可条件的部分自主实现，并承担系统执行、通知释放和增强恢复的验证责任。

严格计时在原生会话入口执行，不能只隐藏前端按钮；全局/独立名单在开始时固定为本轮有效名单。应用限制、严格计时、通知拦截与六项增强分别配置、按实际能力反馈，系统必要交互和故障恢复有明确出口。最近任务隐藏、图标隐藏或动态壁纸不被描述成系统强停免疫；真正设备管理策略需要相应身份。采用开源源码保留对应版权许可，第三方 SDK 和未证实的通知释放/保护路线须先完成技术探针。完整功能范围与验收见[开发规格](../focus-control-spec.md)。

2026-11-15 用户要求完整覆盖 12 张截图，本 ADR 随之纳入锁机、独立白名单、通知拦截与六项保护。状态 proposed 表示架构待第三方来源适配及技术探针验证，尚未执行代码改造；不得将旧“仅免打扰/仅全局名单”的范围作为当前实施依据。

2026-11-15 to-spec 续写补齐已有原型的锁机、放行通知与故障恢复操作默认，见[执行规格](../focus-control-implementation-spec.md)。这次同步修正原 ADR 仅列 Foqos 的过时来源描述；第三方来源适配、系统能力与恢复路线仍需验证，因此保持 proposed，不将候选研究或产品规则补齐标为架构已经通过实现验证。
