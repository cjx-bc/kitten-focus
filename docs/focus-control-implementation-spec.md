## Problem Statement

用户已经使用小猫专注组织待办主题、反复选择子待办、进行正计时或倒计时、休息和查看实际专注投入，但计时本身不足以减少应用与通知干扰。用户希望在原有界面和流程中获得完整的学霸模式、严格模式、通知拦截、全局与独立白名单、独立锁机以及六项增强保护。

现有源码调研找到了能复用的应用控制、限时规则、防篡改和通知暂缓实现，但没有一个或两个仓库可以少量修改后证明完整覆盖需求。用户明确要求：找不到的部分自行实现，而不是删除需求、用免打扰代替通知拦截、用权限诊断代替六项增强，或只做界面开关。

用户还需要知道当前究竟有什么保护在运行。偏好开启、系统授权、服务连接、设备支持和本轮执行成功必须分别表达；失败和恢复不完整必须可见。新增控制不能损坏原有计时、五分钟休息、记录、统计、日历、更新及备份恢复。

## Solution

在现有小猫专注中内置一套由原生端统一协调的专注保护。继续使用原有 Vue 界面和组件风格，通过现有 CatFocus 边界提供配置、开始、状态、临时放行、结束和恢复能力，专注与锁机共享单一活动控制所有权。

优先适配已经核验的 Curbox 控制与通知暂缓模块，以及 DetoxDroid 的精确防篡改、权限身份区分和恢复记账思路。逐文件确认复用许可、来源、改动和依赖；无法适配、没有现成实现、与本项目行为冲突或无法满足许可条件的部分，由本项目独立实现。保留现有 Java 计时与 SQLite，不引入第二套会话引擎或整套第三方 UI。

所有正式需求持续保留。通知提前释放、壁纸恢复、防关闭与设备身份等存在平台边界的能力，先执行技术验证，再实现可行路线并记录真实支持范围。自行实现表示承担开发责任，不表示未经验证便承诺普通权限可以突破系统限制；验证受限必须保留需求、证据与后续处置，不把失败默认为已完成。

## Implementation Decisions

1. **完整范围固定**：学霸模式、严格模式、通知拦截与释放、全局及独立名单、独立锁机、六项增强、权限与帮助、临时放行、异常恢复和旧业务回归全部属于交付范围。开源没有覆盖的部分由本项目承担实现，不删除、不用静态说明替代执行。
2. **保持现有前端**：沿用 Vue、现有五栏图标导航、Sheet、Icon、颜色、字体、间距、输入框与按钮。专注保留原有大数字及圆形控制；新增保护详情由紧凑入口展开，不引入候选应用 UI 或额外宣传框架。
3. **复用策略**：优先适配已经固定提交核验的 Curbox 应用控制、限时退出约束与通知暂缓模块，以及 DetoxDroid 防篡改、身份检查和恢复记账模块。先记录文件来源、许可证、版权、修改及依赖。仅在许可条件清楚且与工程兼容时复制代码；不满足时独立实现相应能力，不擅自改产品分发许可。
4. **架构延续**：现有已接受的 Vue/Capacitor/Java、本地优先和可复用子待办决定继续有效。新增专注控制架构决定仍需反映实际技术验证与最终来源选择；不因选型研究或本规格把 proposed 状态改为 accepted。
5. **单一会话权威**：Java FocusEngine、RestEngine 和 SQLite 继续负责既有实际专注时长与记录。新增控制协调器管理专注/锁机的活动所有权、开始检查、本轮配置、执行及清理，不能并行启动第三方 SessionManager 或新增第二套业务数据库。
6. **主接口边界**：扩展现有 CatFocus 桥接，覆盖配置读写、应用查询、能力检查、锁机开始与结束、临时放行、保护状态和恢复；原有专注与休息入口保持兼容。前端请求结果由原生返回，不在 Vue 推断系统授权或执行成功。
7. **状态分层**：持久偏好、编辑草稿、本轮只读快照分别管理。快照包含控制会话标识、类型、严格约束、有效名单来源与包集合、实际启用能力、增强选项、期限及放行状态；运行中偏好修改仅用于下轮。
8. **名单语义**：持久配置显式区分跟随全局和独立包集合；空独立集合不代表继承。全局在每轮开始解析，独立覆盖且不合并；应用按包标识匹配，未安装配置保留并标记不可用。本应用与必要系统例外单列。
9. **事件执行只读化**：无障碍服务从控制快照读取规则并调用原生阻挡页；必要例外先判断，窗口事件节流和页面去重。现有计时 read 可能结算和写库，不能在每个窗口事件中调用它获取阻挡判断。
10. **严格约束在原生执行**：所有能暂停、取消、提前结束、替换活动会话或发起放行的原生入口统一检查严格倒计时。正计时保持正常结束；严格计时与增强防退出分别配置，不隐式激活管理身份。
11. **临时放行事务化**：只允许普通学霸模式，固定 1/3/5 分钟、每轮三次和单目标；检查、写入与扣次原子完成。请求幂等，取消和失败不扣；重建不延长，不使用每次打开重置的内存计数。结束、休息、重启中断与备份恢复清理放行。采用已有原型方案：放行只改变目标应用的可打开状态，不将其加入本轮通知允许名单，也不主动释放该应用已暂存通知。
12. **通知独立模块**：按本轮有效白名单处理普通通知，来电、闹钟、紧急及控制通知例外。优先使用保留原通知身份的系统机制，不以永久取消或小猫代发原应用消息通过释放验收。
13. **通知缺口自行攻关**：正常到期、提前结束、正计时、取消锁机、休息、服务失联和重启分别验证释放路线；建立会话与通知键归属、更新/撤回/去重及清理状态。请求清理与验证恢复分别记录，发出请求不显示为已经释放；未能实现提前立即释放时，记录准确等待与身份/版本条件，保留未完成项，不宣称已解决。
14. **隐私与声音分离**：通知处理默认仅保留必要键、来源和状态，不建立长期正文库、不入备份与敏感日志。勿扰为可选声音辅助，只撤销本应用规则，默认保留来电、闹钟和媒体。
15. **FORCE-01 自研补齐**：实现待办计时中桌面/最近任务限制，区分普通必要导航、授权窗口与主动启用的增强；到期撤销，紧急和故障恢复保持可达。实际设备行为单独验证。
16. **FORCE-02 自研补齐**：对本应用任务卡片按活动会话切换隐藏，记录原任务状态并在结束、休息或恢复后还原。不能用永久隐藏 Manifest 标志代替生命周期恢复。
17. **FORCE-03 自研补齐**：原生启动入口与 Vue 路由统一识别活动锁机；启用后只进入锁机控制页，授权、帮助、紧急与恢复除外；非锁机时恢复正常业务入口。
18. **FORCE-04 自研与验证**：实现壁纸辅助保护的主动启用、系统确认、状态记录、实际服务重连增益检查和恢复。不能静默更换壁纸，原状态无法完整恢复时明确报告；未经实测不承诺保活或防强停。
19. **FORCE-05 拆分适配**：只选择一套防篡改执行器，针对本应用关闭运行、卸载和关键撤权的特定入口，有界扫描、去重、必要系统操作例外和本轮启停；不同时运行两个候选的返回/回桌面逻辑。
20. **FORCE-06 自研补齐**：使用可恢复启动入口控制隐藏本应用桌面图标；隐藏前验证备用入口，按本轮原状态在结束、故障、重启及升级处理时恢复，失败可见并可重试。
21. **身份和实际能力**：分别检测普通授权、普通管理员和额外管理后端，返回可用、需授权、受限、未支持及原因。设备所有者相关能力不得通过普通开关冒充；不自动执行设备重置、owner 配置或其他高影响操作。
22. **恢复统一记账**：修改系统状态前持久记录本轮原状态与恢复责任；操作失败不丢责任。正常结束、提前结束、休息、锁机解除、重启中断和备份替换走幂等清理；只撤销本应用变更，保护用户后续主动选择。有会污染下一轮的旧图标、任务、壁纸或策略状态未恢复时，阻止启用有冲突的新保护并给出修复入口，不能用新一轮覆盖旧恢复责任；无关核心功能继续可用。
23. **故障恢复不改写事实**：入口位于权限与保护状态、帮助、锁机控制页及活动控制通知。隐藏图标或禁止主界面前，先验证这些替代入口可达。操作使用原有 Sheet 列出本轮受影响项目、计时保留及恢复结果含义；取消不操作，确认后按本轮记账撤销应用限制与增强更改、停止通知拦截并尝试释放。逐项显示已恢复、失败或系统受限，失败可重试；不删除名单/偏好，不结束计时、不暂停严格倒计时、不伪造完成。用户主动撤销的能力本轮不因重连再次启用，下轮重新按偏好检查；临时失效后的授权修复仍只恢复本轮原先启用且未主动撤销的能力。
24. **锁机会话独立语义**：采用已有原型的可配置倒计时及普通/严格两种锁机。普通锁机可以确认提前解除，关闭或取消确认则继续；严格锁机开始前明确提示不能暂停、取消或提前解除，开始后由原生统一拒绝相关操作，到期自动清理。两者均可进入帮助和故障恢复，但恢复不把严格会话标为结束。锁机使用独立会话类型与记录，不写入专注记录、不增加专注次数/时长或日历实际专注，也不自动进入五分钟休息；正常到期或普通解除后显示锁机结果并可返回待办。设备重启时中断锁机并清理，不自动重新强锁。
25. **备份与迁移**：持久业务备份包含偏好、名单与锁机配置，不包含活动控制、临时放行、通知正文或系统授权。兼容旧 schemaVersion=1 备份；恢复后重新检测安装包与权限。手动业务恢复和本机升级恢复都必须排除活动保护重激活。
26. **兼容边界**：维持当前 min24 / target36 目标，不因候选 min26 自动提高最低版本。按 API/身份门禁隔离新能力，低版本不能被静默替换为不同效果；有需求无法在某环境满足时记录具体失败与证据。
27. **原有休息不改**：正常倒计时到期及正计时正常结束后沿用五分钟休息；倒计时提前结束保留手动休息入口；休息无暂停、退出需确认、结束后手动再次专注。休息释放本轮控制但不增加专注统计。
28. **交付是行为而非开关**：交付源代码、可审阅 APK、逐项结果与已知限制。一个选项存在、许可保留或原生 API 调用成功都不能单独代表功能验收通过。
29. **执行与探针分开完成**：先为通知、壁纸及防关闭提交可重复探针和设备结果，再接入统一控制；探针失败必须记录可复现条件与剩余缺口。规则层、桥接与界面可以按依赖推进，但技术探针或前端交互完成不表示全部系统功能交付；最终仍逐项满足下列验收条件。

## Testing Decisions

1. **已确认的主要测试边界**：用户已明确采用现有 CatFocus 原生桥接为主要验收入口，覆盖开始、严格限制、临时放行、结束、休息与恢复；通知、桌面、图标、壁纸实际效果由安卓设备场景补测。
2. **优先外部行为**：好的测试从桥接命令、返回快照、实际应用/通知效果和持久恢复结果判断，不断言私有方法、类调用次数或候选库内部结构。不为每个实现类新增一套公开测试接口。
3. **尽量共用一个入口**：配置、会话与保护在同一原生协调边界观察；设备适配器与受控时钟可用于确定性模拟失败、到期和重建，不改变对用户暴露的产品接口。少量难以在桥接证明的系统效果保留设备集成测试。
4. **沿用既有测试先例**：FocusEngineTest 已有到期封顶与只记一次、暂停扣除、同次开机重建、重启中断及暂停时拒绝第二会话；沿用这些行为场景扩展保护，不把其读取内部存储的测试写法当作新增测试必须复制的结构。
5. **沿用领域先例**：现有 domain 测试覆盖专注结算、统计与备份；rest 测试覆盖固定五分钟、正计时正常结束、延迟唤醒、提前结束手动休息和休息不计统计。新增用例保持这些外部语义。
6. **模式与名单矩阵**：验证三个独立开关组合、首次全关、权限拒绝；全局继承、独立覆盖、独立空名单、恢复跟随、筛选保留、取消不保存、运行中修改只影响下轮、必要例外与未安装包行为。
7. **严格入口矩阵**：严格倒计时通过页面、原生通知操作、桥接、会话替换、恢复界面尝试暂停/取消/结束/放行均拒绝；正计时仍可正常结束；普通暂停仍限制，休息才释放。
8. **临时放行矩阵**：1/3/5 分钟、三次耗尽、单目标替换、取消/失败不扣、重复请求幂等、并发请求原子性、暂停不延长、进程重建不重置、会话结束清除及严格拒绝。
9. **通知双应用验证**：使用独立测试通知发送端和接收控制端检查原包身份、点击行为、正常到期、提前结束、正计时、取消锁机、休息和故障恢复；覆盖更新、撤回、分组、重复、不可清除、工作资料以及监听断开。不能仅观察小猫自己发出的通知。
10. **六项增强逐项设备验证**：分别验证关闭/开启、拒绝权限、执行失败、到期撤销、用户后续改动不被覆盖、进程死亡与重启恢复；同时验证组合启用后的恢复通道。图标、壁纸和任务卡必须检查真实原状态与恢复结果。
11. **生命周期与隐私**：进程重建与设备重启分开；原生权限撤回、服务重连、用户明确降级、备份恢复和升级恢复分别测试。检查敏感正文不入日志/备份、只清理本轮自有状态、失败仍可见并可重试。
12. **设备与版本证据**：MuMu Android15 用于开发联调；API24/25、26+ 与目标现代系统覆盖能力门禁。真实来电、紧急拨号、OEM 后台、实际壁纸和 launcher 行为补真机；模拟器不能代替这些结果。测试使用隔离数据或保全已有数据，不能直接运行会清空用户当前数据的测试准备逻辑。
13. **构建与旧业务回归**：执行与改动相关的规则/集成测试、TypeScript 检查、前端构建、Android 编译与 APK 构建；待办、专注、休息、日历、统计、更新和两类备份恢复按既有行为回归。
14. **原验收编号继续有效**：A01 面板、A02 权限、A03 列表、A04 模式、A05 继承、A06 通知、A07 通知帮助、A08—A13 六项增强、A14 完整帮助、A15 锁机、A16 放行、A17 快照恢复、A18 旧业务逐项记录通过/失败/受限/待设备验证及证据。受限或待验证不能算全部通过。
15. **续写交互验收**：普通锁机取消确认继续运行、确认后解除；严格锁机所有提前解除入口拒绝但恢复可达；锁机不计专注和不启动休息；临时放行不连带释放通知；故障恢复取消无副作用、确认不停止严格计时、结果真实、失败可重试、主动撤销本轮不自动重启；旧恢复责任不被新会话覆盖。

| A11 | 记录原壁纸，启用/拒绝 FORCE-04，检查关联服务增益，正常/异常结束并主动修改壁纸后恢复 | 只在用户确认后施加；有真实重连/启动效果证据；恢复原状态或明确报告限制；不覆盖用户后续选择，不把设置成功当保活证明 |
| A12 | 开启 FORCE-05，访问本应用强退/撤权/卸载入口及无关设置，在普通权限和额外身份下分别验证 | 精确限定目标，必要设置可用；行为与真实权限一致；到期及恢复后撤销；语言/OEM 差异有结果；无授权不宣称系统防卸载 |
| A13 | 隐藏图标前检查替代入口，开启 FORCE-06 后结束、故障、进程死亡、重启与升级恢复 | 未验证可达入口不隐藏；隐藏/恢复只影响本应用启动入口；通知与控制页可恢复；原状态不丢，失败明确可重试；不等同包不能卸载 |
| A14 | 离线浏览模式、名单、通知、增强、系统身份及排障；从图标隐藏和主界面限制组合进入恢复 | 每类帮助有正文；示例与正式规则一致；真实限制不被宣传承诺覆盖；恢复列明影响，取消无操作，确认后结果逐项可读 |
| A15 | 创建并重用普通/严格锁机配置，切换名单，缺权限开始，和专注/休息互斥；到期、提前解除和重启 | 配置可复用；开始前检查与降级明确；普通解除需确认、严格提前解除拒绝；剩余时间与实际状态准确；记录独立、不计专注、不自动休息；结束/中断清理真实 |
| A16 | 依次放行 1/3/5 分钟，取消、执行失败、并发重试、换目标、暂停、重建、到期及严格请求 | 成功才扣、每轮最多三次、同一时刻单目标；期限不延长、次数不重置；不改永久名单、不连带释放通知；严格入口原生拒绝 |
| A17 | 运行中编辑，失联再修复，进程重建，设备重启，主动恢复后重连，带未清理状态启动下一轮 | 本轮快照和已用次数稳定；临时失效只恢复原能力；主动恢复能力本轮不自动重新开启；重启中断不计间隔；恢复责任保留、冲突新保护被阻止且可修复 |
| A18 | 回归待办、正/倒计时、实际记录、五分钟休息、日历/统计、更新；读旧备份及手动/升级恢复 | 常驻子待办和历史语义保持；休息固定五分钟、不计统计、不自动下一轮；旧备份可读；活动状态/通知正文/授权不被恢复为有效保护；记录不重入、已结束控制不残留 |

## Out of Scope

- 改变原有产品视觉风格、五栏导航、待办常驻语义，或引入候选应用的完整 UI。
- 整体替换现有计时、SQLite、记录与统计，或同时运行第二套会话引擎。
- 周期锁机、定时排程、跨设备控制、家长远程管理、网站/短视频内容过滤等未在本轮正式需求中提出的扩展。
- 账号、云同步、AI 助手、宠物养成、商店、金币经验和手动补录专注时长。
- 自动激活设备所有者、重置日用设备、静默授予权限或修改其他应用系统状态的部署操作。
- 永久无法卸载、百分之百防强停、未经验证的壁纸保活或任意 Android 身份/版本都能无损恢复通知的承诺。
- 把“未找到现成实现”“工程困难”或“当前设备不足”作为删除本规格正式功能的理由。
- 本次 to-spec 操作不自动提交、推送、发布 APK 或开始整套功能编码；当前产物为规格。

## Further Notes

- 本次用户明确授权的产品方向是：现成部分复用，缺失部分自主实现，范围不缩减，原有样式不改。不存在“只交一个开关面板”或“只做权限诊断即可完成”的替代范围。
- 测试边界已经用户在本轮明确回复“采用这个测试边界”，不需要再次确认。
- 本次按继续完成 to-spec 的要求，将此前原型已有的五处方案写为可执行规格默认：普通锁机确认解除、严格锁机到点结束、锁机记录独立且不计专注/不自动休息、放行不连带释放通知、恢复入口与确认/逐项结果/重试。具体规则已合入 Implementation Decisions 与验收矩阵，不再用“细节待定”代替这些操作定义；这不回写为用户历史上已逐项确认。
- 后续工作是按技术探针、配置与统一会话、原生控制、通知、锁机与增强、原有样式界面、设备回归依赖推进实现。平台技术结果、代码复用许可兼容和设备覆盖仍需真实核验；它们不等同于产品操作规则缺失，也不能用来缩减范围。
- 通知原身份提前释放、壁纸原状态恢复、防关闭支持范围属于开发验证责任，不要求用户猜测底层 API。验证无可行路线时报告具体缺口及可评估选择，不能擅自改成永久删除或不同效果。
