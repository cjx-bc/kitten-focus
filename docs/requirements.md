# 小猫专注：需求与访谈记录

更新时间：2026-11-14。

状态：四轮访谈和 Q32 整体确认均已完成，用户回复“确认”，现进入实现与验证阶段。本文保留访谈过程；面向实施的汇总见 [第一版规格](v1-spec.md)。

## 已确认的产品基线

- 产品名称：小猫专注。
- 目标平台：安卓。
- 主要场景：学生日常学习，以可在手机上实际使用作为验收目标。具体是自用、毕设还是公开发布尚未补充，不据此假定上架运营需求。
- 按单人开发、分阶段产出可安装版本规划；用户未提出硬性截止日期。
- 底部导航顺序：待办、日历、小猫、统计、我的。
- 整体 UI 全面参考 iOS「小鸡专注」的设计；用户此前提供的待办、专注和统计截图作为功能和结构参考。截图没有覆盖的界面仍需按统一设计语言补齐，尚未验收具体设计稿。
- Q29 用户再次强调按「小鸡专注」参考，未接受助手单独提出的“默认跟随系统、先纯色背景、背景功能统一延期”组合建议。外观选项与背景呈现须依据参考资料对照，不能把该建议记为既定需求。参考图已保存于 [references](references/README.md)。
- 待办采用“大主题 + 子待办”的层级，点击子待办的开始按钮进入专注页。
- 子待办是长期保留、可反复选择的专注事项，支持编辑和删除，不设勾选完成或已完成列表。移除待办计划日期，具体时间安排统一由日历负责；此条按 Q17 取代早期 Q10 的计划日期建议。
- 主题包含名称、颜色，支持排序、展开和折叠；子待办支持标题、可选备注、计时模式、倒计时时长和排序。
- 编辑或删除待办不丢失历史专注记录；历史保留当时名称与时长，改名不拆散同一事项累计统计。待办删除后关联日程保留标题和时间、解除关联。删除主题时允许选择连同下属待办删除，或将它们移到其他主题。
- 第一版保留小猫导航入口，页面只显示“小猫还未入驻”。第一版不实现宠物、商店、互动、升级或进化，也不发放金币和经验；这些整体后移。
- 专注支持正计时与倒计时；倒计时默认 25 分钟、允许修改，创建子待办时选择模式。
- 默认首页为待办；子项展示名称、模式/时长、今日专注次数/时长和开始按钮，另有自由专注入口。未结束的专注在待办顶部提供返回入口。
- 专注为独立全屏页面，隐藏底部导航；返回待办不结束计时。倒计时按分钟配置，提供 25/45/60 分钟快捷项。结束后显示实际时长、暂停时长和状态，可再次开始或返回待办。
- 允许直接开始不关联子待办的自由专注；从子待办开始时自动关联对应任务。
- 普通专注允许切换应用和锁屏并继续计时；支持暂停/继续，暂停时间不计入专注。同一时间仅允许一条未结束的专注（包含暂停）。允许提前结束并保存实际时长；倒计时到点结束、正计时手动结束。第一版不做自动循环番茄或自动休息。
- 同次开机内意外退出后，重新打开恢复原专注并补算经过时间；设备重启后将原专注记为中断，保留最后已保存时长，不计入重启间隔。
- 第一版历史专注记录支持查看、删除，不支持手工补录或改时长；删除后统计同步更新，不影响待办。
- 正计时手动结束视为正常结束；倒计时未达到目标主动结束才标记提前结束；重启造成的结束标记中断。
- 日历支持手动安排个人日程、课程表，提供时间轴式展示。普通日程包含标题、起止时间、可选备注和可选子待办关联，支持单次、全天与按周重复；时间冲突提示但允许保存。
- 课表采用学生学期模型，支持学期、周次、节次与单双周，教师和地点可选。每周周一开始，学期第一周以用户选择的周一起算，总周数、节次时间可配置；课程支持指定某次停课或调课而不影响其他周。普通重复日程支持仅本次或整组修改、删除。
- 日程与子待办独立存在，可选关联：未安排时间的子待办也能专注；课程可独立作为日程；关联时共用同一项任务，不重复生成待办。
- 日历保留原计划，实际专注记录另行呈现，可切换查看计划和实际；专注结束不改写计划时间，叠加视图尚未确认。
- 日历分日程/课表入口；日程顶部一周日期条可展开月历，下方切换计划/实际时间轴；课表为一周时间轴、按节次排列并可切周。支持多个学期，选择一个当前学期，旧学期保留查看。
- 个人日程允许跨天；课程节次在当天内，开始早于结束。日程按设备当地时间安排，历史按发生时当地日期归属，换时区不改写旧记录；周一起算，月/年按自然月/年。
- 统计支持日/周/月/年/累计，展示时长、次数、专注天数、平均时长、主题/事项占比、趋势、时段分布和历史记录入口。移动待办到新主题不改写旧记录的主题归属。起床、睡眠打卡和 App 使用统计后移，首版不收集或统计打断原因。
- 统计累计实际专注时长，扣除暂停；提前结束与不足一分钟的实际记录都保留并计入。每条专注记录计一次，次数归开始日，跨午夜的实际时长按日期分配；自由专注单独分类。
- 专注中展示计时通知，到点可播放声音和振动且允许关闭。日程和课程提醒默认关闭，逐项开启后默认提前 10 分钟；权限拒绝时的产品行为待最终规格明确。
- 我的第一版包含专注默认设置、显示/声音偏好、本地数据导出与恢复、关于。
- 备份文件包含全部已保存业务数据与设置；恢复采用整体替换，不合并，展示备份日期并再次确认。必须先结束当前专注再恢复。
- 第一版不做 AI 助手。
- 第一阶段采用免登录、本地完整使用的版本，核心功能离线可用；账号与云同步后续接入。
- 强力锁机明确移出第一版，后续最后研究实现。
- 第一版交付物为可安装安卓 APK、全部源码和中文运行安装说明；需真机离线验收待办重复使用、专注暂停/锁屏恢复、日历课表、统计与备份恢复。

## 未来功能意向

宠物养成整体移到后续版本：专注获得金币与经验，金币用于购买小猫房子、玩具等物品，经验推动升级、进化或解锁成长形态。养一只还是多只、奖励资格、发放时机、成长数值和具体互动均未决定；先前“一只长期陪伴小猫”的建议不视为用户已接受。

AI 助手计划支持闲聊、通过对话安排日程、识别课程表图片并整理到日历、解答项目功能与宠物养成攻略，以及结合待办、专注和统计提供辅助。以上均不属于第一版；AI 的操作权限、执行确认和模型服务尚未确定。

强力锁机计划参考现有项目再研究整合，已确定不属于第一版；权限、运行模式与可覆盖设备尚未确定。

## 设计决策树

- 交付条件：用途与用户、开发人数与期限 → 首个版本范围、发布与验收方式。
- 数据与身份：免登录 / 登录、离线范围、首版同步需求 → 备份、账号迁移、同步与冲突处理。
- 规划模型：日程与子待办的关系 → 重复日程、课表周次、任务复用、日历计划与实际的展示。
- 专注模型：正计时 / 倒计时、是否必须绑定待办、切后台是否继续 → 暂停与休息、结束与中断、异常恢复、记录修订。
- 养成模型（后续版本，当前不展开）：一只长期陪伴 / 多只收集 → 奖励资格与结算、等级和形态、物品购买与使用、失败反馈。
- 统计模型：依赖专注记录和任务归属的规则 → 指标口径、筛选、历史变化与截图附加项目。
- 界面与素材：已确定参考方向及五栏导航 → 各页面具体信息、素材和交互验收。
- 系统功能：依赖交付与专注模型 → 通知提醒、权限拒绝、锁屏与重启、最终锁机阶段。

## 实现与验收约束草案

以下为实现质量要求，随最终规格一起审阅，不视为新增业务功能。

- 提醒权限被拒绝时，计时、日程和本地数据功能继续可用；清楚提示提醒未开启，提供设置入口，不反复强制弹权限申请。
- 备份导入前检查文件格式和支持的版本，文件损坏或不兼容时不替换当前数据；校验通过并确认后才进行整体恢复。
- 仅正实际时长形成统计记录，零时长不产生专注次数；同一专注只保存和结算一次。
- 删除记录与恢复数据后，统计和日历实际记录保持一致；备份只包含已保存数据，不把未结束的专注当成可恢复运行状态。
- 调整系统日期时间不直接改变同次开机内已过去的专注时长；异常和权限行为在真机验证，不仅检查网页预览。
- 公开资料未覆盖的界面按统一设计语言设计，首版不为尚未开发的 AI 或锁机增加可点击的空功能入口；小猫占位是用户明确指定的例外。
