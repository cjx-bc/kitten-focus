## 能确认什么

番茄的学霸模式是计时以外的一层应用使用限制。官网确认分心警告；安卓商店确认减少其他 App 干扰、白名单搜索及专注悬浮窗。它不只是把时钟铺满屏幕。[S2][S3]

| 功能 / 声明 | 第一手证据及边界 |
| --- | --- |
| 允许名单与应用识别 | 隐私政策称应用列表、使用情况用于学霸模式/锁机时判断白名单，并用于 App 前台运行时长统计。[S1] |
| 悬浮显示 | 政策将悬浮权限关联到学霸、锁机和专注悬浮窗；商店提供计时页右上角开启悬浮计时的入口说明。[S1][S2] |
| 电话例外 | 政策称读取通话状态用于避免电话程序被误拦截。[S1] |
| 通知管理 | 政策声明可选的专注通知拦截；这段说明没有指出具体 Android API。[S1] |
| 额外强制能力 | 政策称少数机型可主动开启设备管理器以提高强制性；拒绝不影响其他功能。[S1] |
| 稳定性与屏幕 | 政策说明电池优化豁免、开机恢复锁机、前台服务及屏幕常亮的用途。[S1] |

以上是**官方功能/权限用途声明，不能当作当前安装包内部实现的证据**。S1 页面标注 **2023-10-13** 更新；S2 当前渠道版本为 **10.2.9.519，2026-11-11**，包名 `com.plan.kot32.tomatotime`。商店更新文案可能累计保留旧条目，不能据此确定各功能首次上线日期。[S1][S2]

## 可以怎样理解，哪些不能下结论

工程推断：已公开的能力可以组成“识别应用 → 判断允许名单 → 提示或阻挡 → 计时结束释放”的控制流程；悬浮计时、通知管理和恢复机制辅助这条流程。**这只是对公开声明的架构解释，并非还原番茄源码。**[S1][S2][S3]

- 未证实番茄当前以无障碍服务实现拦截，也未证实其具体轮询频率、阻挡窗口类型或后台拉起策略。
- “通知拦截”功能声明不能证明使用 `NotificationListenerService` 或勿扰策略；商店的 `POST_NOTIFICATIONS` 项也只能证明发布通知权限声明。[S1][S2]
- 普通设备管理器不等于 Device Owner；没有证据可将番茄描述为依赖 Shizuku、root、VPN 或冻结应用。Android 机制边界另见[控制能力调研](../android-focus-control-research.md)。
- 本轮未取得当前安卓版本严格退出、暂停次数/秒数、临时放行额度、收费边界和完整锁机规则的官方说明，不能把历史数字写成需求事实。

## 我们已有基础与缺口

下表来自本仓库源码静态检查，未执行真机验收。

| 源码 | 已有基础 / 缺口 |
| --- | --- |
| [`FocusEngine.java`](../../android/app/src/main/java/com/xiaomao/focus/FocusEngine.java) | 正/倒计时、暂停恢复、单调时钟锚点、会话持久化、重启检测、结束状态与休息衔接；重启按中断结算，不是自动继续严格锁机。 |
| [`Reminders.java`](../../android/app/src/main/java/com/xiaomao/focus/Reminders.java)、[`ReminderReceiver.java`](../../android/app/src/main/java/com/xiaomao/focus/ReminderReceiver.java) | 到点提醒、通知、闹钟以及开机/时间变化后的处理；这些不能自动提供其他应用的拦截能力。 |
| [`CatFocusPlugin.java`](../../android/app/src/main/java/com/xiaomao/focus/CatFocusPlugin.java) | 已有 Capacitor Java 桥接及通知/精确闹钟权限状态；可沿用桥接方式增加独立控制接口。 |
| [`AndroidManifest.xml`](../../android/app/src/main/AndroidManifest.xml) | 尚无应用识别/拦截服务、Usage Access、悬浮、通知监听、DND 或前台服务声明。 |

建议先补控制闭环，保留当前计时引擎作为会话权威来源。以下是本项目建议，**不是番茄的已验证规则**。

| 优先级 | 要补的功能 | 可验收的结果 |
| --- | --- | --- |
| **P0** | 允许名单选择与搜索、受限应用识别、原生阻挡/分心提示；电话和系统必要功能放行 | 开始专注后能打开学习工具，打开受限应用有明确阻挡；拨号、来电、紧急操作、输入法及必要系统界面不被误挡。系统例外按设备角色识别，不硬编码单一 ROM 的包名。 |
| **P0** | 原生控制状态与权限检测、同一会话 ID 的开始/暂停/恢复/结束、权限丢失和后台异常恢复 | UI 能区分“计时中”和“限制有效”；完成、取消、休息、重启中断均清理限制；服务失效有原因提示，不显示虚假的保护成功。暂停是否解除限制作为产品规则明确决定。 |
| **P1** | 独立可选通知管理、悬浮计时、分心事件与后台诊断 | 通知授权与发布提醒分开；恢复自己修改的策略；悬浮时间跟随权威会话；记录中断时间/原因，不采集其他应用正文。 |
| **P2** | 用户选择的严格退出规则、Shizuku/受管设备后端、网站/内容限制 | 有明确需求后独立验证；不用高权限配置阻碍首次专注；支持失败降级和结束恢复。严格模式先定义规则，再选机制。 |

默认产品路线应是普通安卓用户可理解、可撤销的应用限制。实现可以选择自建原生控制模块或先做外部联动验证，技术选型和许可约束见[已有开源调研](../android-focus-control-research.md)。不要因为竞品称“锁机”，就承诺普通安装能获得系统冻结能力。
